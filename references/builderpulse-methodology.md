# BuilderPulse 五维分析框架

从 6 大全球平台采集的原始数据，通过以下五个维度进行系统性分析，输出可执行的商业机会洞察。

## 框架概述

```
原始数据（6 个数据源）
    ↓
阶段一：信号提取 — 从原始数据中提取有意义的信号
    ↓
阶段二：交叉验证 — 多源比对，判断信号置信度
    ↓
阶段三：五维分析 — 分类进入五个分析维度
    ↓
阶段四：评分融合 — 结合四维评分模型输出最终机会卡
    ↓
阶段五：行动触发 — 基于 profile.md 给出具体构建建议
```

## 五个分析维度

### 1. 发现机会

回答：有什么新产品？有什么需求没被满足？

数据来源与信号类型：

| 信号 | 来源 | 提取方式 |
|------|------|---------|
| 独立开发者产品发布 | HN Show HN + PH | 提取产品名称、功能描述、技术栈 |
| 搜索词异常飙升 | Google Trends | 识别 Breakout 和 +200% 以上的关键词 |
| 快速增长的开源项目 | GitHub Trending | 关注高 star 增长、无商业化版本的项目 |
| 开发者抱怨 | HN 高分帖 + Reddit | 提取被抱怨的产品名和具体痛点 |
| 用户"求推荐" | HN Ask HN + Reddit | 直接需求表达，高付费意愿信号 |

输出格式：
```
信号描述 + 来源数量 + 置信度（高/中/低） + 关联链接
```

### 2. 技术选型

回答：技术风向在变什么？哪些工具在涨/跌？

数据来源与信号类型：

| 信号 | 来源 | 提取方式 |
|------|------|---------|
| 公司关停/降级 | HN 高分帖 | 识别"闭源""停止服务""降级"关键词 |
| 增长最快的开发者工具 | GitHub + PH + HN | 综合排名，关注增速 |
| HuggingFace 热门模型 | HuggingFace | 趋势分 + 下载量 + 协议类型 |
| 技术栈分析 | HN Show HN | 从帖子描述中提取技术栈信息 |

分析重点：
- 哪些技术栈在成为新默认（如 React 19 + FastAPI）
- 哪些旧技术在"复活"（如 DaVinci Resolve 进军照片编辑）
- AI 模型的商业化潜力（协议类型 + 本地可运行性）

### 3. 竞争情报

回答：别人在怎么赚钱？竞争格局在怎么变？

数据来源与信号类型：

| 信号 | 来源 | 提取方式 |
|------|------|---------|
| 收入/定价讨论 | Reddit r/SaaS + r/SideProject | 提取 MRR/ARR 数字、定价策略 |
| 旧项目复活 | HN + Google Trends | 识别沉寂项目的重新爆发 |
| "XX 已死"迁移文章 | HN | 提取用户从什么迁移到什么 |
| 产品对比/竞品分析 | Reddit + HN 评论 | 从评论中提取竞品对比信息 |

分析重点：
- 收入数据验证市场规模（有人做到 $X MRR = 市场存在）
- 迁移方向 = 新机会方向（用户从 A 搬到 B，B 的生态有机会）
- 定价空白 = 机会（现有产品太贵或太便宜，中间地带有空档）

### 4. 趋势判断

回答：大方向在往哪走？什么是噪音什么是信号？

分析维度：

| 分析类型 | 方法 | 输出 |
|---------|------|------|
| 关键词频率变化 | 跨天对比 Google Trends 数据 | 上升/下降/稳定 |
| VC/YC 方向 | PH 热门 + HN 高分公司产品 | 资本关注的赛道 |
| 降温词识别 | 3 个月 vs 7 天窗口对比 | 机会从"教育"转向"工具"的时机 |
| 新词雷达 | 7 天窗口中的全新搜索词 | 最早的 SEO 机会 |

核心判断原则：
- 多源交叉验证 = 高置信度（如 Google Trends 飙升 + HN 热帖 + GitHub 趋势同时出现）
- 单源信号 = 低置信度，标记为"待观察"
- 持续 6 个月以上的趋势 = 结构性变化，非一日热点

### 5. 行动触发

回答：我今天/这个周末应该做什么？

生成规则：
1. 从前四个维度中筛选出最值得投入的方向
2. 结合 profile.md 的能力矩阵，评估"能不能做"
3. 对比资源约束（资金 ≤500/月、时间不固定、一人），评估"做不做得了"
4. 输出具体建议：

```
最佳 2 小时构建：XXX
- 验证来源：XXX 帖子/数据
- 痛点强度：XXX（来自哪个源的什么数据）
- 毛利率估算：XXX
- 最快验证步骤：XXX

为何不选 YYY：
- 原因 1
- 原因 2
```

## 信号置信度分级

| 级别 | 标准 | 符号 |
|------|------|------|
| 高 | 3+ 数据源同时出现相同信号 | ★★★ |
| 中 | 2 个数据源交叉验证 | ★★ |
| 低 | 仅 1 个数据源 | ★ |

## 与四维评分模型的关系

五维分析是**阶段二（AI 过滤）**的增强版分析框架。分析完成后，产出的机会仍然进入**阶段三（四维评分）**进行打分：

```
五维分析 → 提取 N 个候选机会 → 四维评分模型打分 → 总分 15+ 重点关注
```

五维分析的"交叉验证"结果直接辅助评分：
- 高置信度信号 → 痛点强度和付费意愿维度加分
- 多源竞争情报 → 竞争空白维度参考
- 趋势判断 → 市场时机参考
